What makes a specialist?

01 / ISOLATED MEMORY

A frozen domain ledger

A dedicated trinity_memory.db holds the local LTKG and rejected-claim ledger. Promotion freezes the specialist baseline read-only.

02 / DOMAIN CHARTER

A hash-verified contract

charter.md defines posture, epistemic rules and domain boundaries. SHA-256 integrity checks bind the deployed artifact to its verified version.

03 / BOUNDED EXECUTION

Mechanical limits

The design enforces max_depth = 1, write isolation and deterministic commit gates outside model prompts. A specialist cannot directly rewrite the parent graph.

Workshop → production → evolution

STEP 01

Seed in the Workshop

Use a structured 10-step curriculum to load domain invariants, record industry myths as rejected claims and test messy edge cases. This develops the specialist ledger, rather than retraining model weights.

STEP 02

Freeze & verify

Promote the Workshop database and charter to a SHA-256-verified, versioned artifact in the Foundry Registry.

STEP 03

Deploy in isolation

Run the specialist in a separate git worktree on a dedicated local port. A worktree separates files; write permissions and runtime guards must enforce the authority boundary.

STEP 04

Version & evolve

Return new edge cases to the Workshop and promote a new version, such as v1.1.0. Preserve the verified baseline instead of overwriting it.

Same engine. Three scales.

Use a Solo Cell for repeatable domain checks, a Cortex Set for cross-domain review, and META_TRINITY to manage a roster of both.

Request boundaries and failure handling

The specified pin() snapshot fixes mode, exact profile hash and policy at the request boundary. A later selection applies to a later request. Unavailable specialists may use a recorded parent fallback; a timeout leaves outcome unknown without automatic resend; malformed or corrupt replies trigger FoundryFailClosed. Integrity checks detect artifact changes; they do not prove that a claim is true.

Origin-tagged rejected claims travel upward through the epistemic relay. The B6.4 consistency gate qualifies or blocks conflicting assertions before parent output, while each cell retains its own memory boundary.
