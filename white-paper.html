About edition 0.2

Updated 14 November 2026. Source-inspected mechanisms, captured interfaces, intended integration and research hypotheses are distinguished throughout. The companion Code Schema remains a separate 0.1 proposal.

Abstract

Trinity Engine uses Artificial Cognition Intelligence (ACi) as its proposed category for cognitive infrastructure in which model inference is a replaceable utility within a persistent software architecture. Coded roles, graph relationships, state transitions and policy determine how context is assembled, candidate outputs are evaluated and authorized information is retained. ACi is a project positioning and architectural model, not an established scientific classification or a claim that deterministic control makes model output deterministic.

This edition incorporates the website’s current working concepts and captured interfaces: distinct Cortex and Raven responsibilities, heterogeneous inference, agentic task Radar, instrumentation, governed memory, relational field demonstrations, hierarchical semantic compression and computational self-reference. It separates source-inspected mechanisms, captured application state, intended integration and research hypotheses. No comparative performance, storage-compression or security benchmark is asserted.

1. The architectural problem

A continuing investigation requires more than a plausible answer. It needs evidence references, persistent context, visible uncertainty and control over what becomes durable state. A model-centred application can provide these features, but they must be implemented outside the model’s probabilistic output. Trinity makes that surrounding infrastructure its primary design object.

The aim is to preserve system-owned identity, memory continuity, topology and policy when the inference provider changes. Provider changes can still alter quality, latency, cost, privacy obligations and protocol behaviour. An API key is an access credential, not a compatibility layer or an enforcement mechanism; adapters and deployment checks remain necessary.

2. ACi: inference as a governed utility

The n + 1 model separates n, a replaceable inference endpoint, from +1, the coded intelligence substrate: Cortex control logic, the LTKG, State Weaver and Oracle Policy. “Any endpoint. Any model. Zero unpoliced execution.” expresses an architectural rule, not evidence that every provider is already integrated or every execution path has passed a security audit.

Foundation-model output is treated as candidate information from an untrusted compute endpoint. It cannot authorize its own memory write, tool invocation or state change. The intended boundary validates scope, stages proposals, applies policy and permits only authorized commits. Deterministic state rules organize inference without guaranteeing factual accuracy or deterministic responses.

This is a comparison of architectural emphases, not a universal claim that other AI systems are stateless, lack governance or use only prompt-level controls.

3. Cortex and coded cognitive roles

CORTEX is the cognition engine. ENG examines constraints and evidence; SYNTH explores connections and alternatives; PRIME evaluates supplied reasoning when host routing invokes it. They are coded cognitive roles served by configured inference calls, not separate chat products or independently conscious entities.

The intended sequence is context construction, role-conditioned inference, configured routing and possible arbitration, response production, then separately governed retention. PRIME is conditional rather than mandatory on every cycle. Heterogeneous shard assignments are visible in current Yggdrasil captures; a screenshot records one configuration and does not establish independence between models or measured benefits from their combination.

4. Raven: Huginn, Muninn and task execution

RAVEN is the agent and user-interface layer. Huginn is the portable Discord-facing role, with economical API inference and configured OpenClaw capabilities. Muninn is the Yggdrasil cockpit role, close to memory inspection, system state and permitted Cortex reads. Roles describe context and authority boundaries; they are not fixed model products.

Direct Remote API chat provides conversation without OpenClaw agent tools or tasks. Agent execution requires the appropriate gateway, host tools, credentials and permissions. Phone access to Discord does not mean the engine executes on the phone. A remote role does not inherit cockpit access merely because both are called Raven.

WARDEN names the governed consultation and action boundary. In the intended design, caller identity, scope, permitted operations and audit records constrain execution. Actual enforcement coverage must be tested at every exposed path; a symbolic role or returned plan grants no permission.

5. Raven Radar and bounded loops

Current application captures show a shared Cockpit task board and Radar, task ownership, workflow states, plans, evidence and completion logs. Huginn and Muninn can pick up tasks through their configured paths, update progress and react to changes. A bounded execution loop may request review, stop at a limit or report a blocker. Loop completion is distinct from task completion: the displayed task contract says Raven cannot mark its own task completed.

Task policy offers Trinity consultation as needed, required or not permitted. A required consultation is a task-contract requirement; displaying that requirement does not independently validate a cryptographic signature. Review, authorization and permitted execution remain separate from planning.

Task-list consolidation on command can propose a revised organization or plan. Resource efficiency is an objective requiring measurement, not a guaranteed saving. Automatic DreamCycle-driven task reprioritization and a specific organizer scheduling contract were not verified by the website implementation work.

6. Persistent records, provenance and ELLIS

The source-inspected LTKG base node schema includes identifiers, labels, types, importance, metadata, first/last-seen timestamps and pruning protection. Edge records include source and target identifiers, relation, weight, confidence, source, reinforcement cycle, timestamps, protection, metadata and query references. A public response schema can expose only a subset of stored fields.

Content and artifact references can be represented through metadata or linked records. Dedicated embedding-reference and lifecycle fields must be verified in their specific storage or interchange layer rather than assumed from the base node table. Weight is not equivalent to confidence, probability or causal strength. Source/target identifiers define a directed record; they do not themselves prove causation.

ELLIS is the Orb Weaver in Trinity’s symbolic vocabulary: the spider within a web of linked evidence, context and continuity. It names the provenance-linking role rather than an autonomous agent. An ELLIS mark does not create an edge, certify a statement or authorize access. The symbolic scaffold can change while evidence references, state rules and permission boundaries remain explicit.

7. Staging, DreamCycle and semantic compression

Source inspection found candidate staging, promotion sweeps, health-held promotion and node/edge upsert mechanisms. DreamCycle code includes summary and embedding generation; Cortex uses a vector-store facade. These are code-level observations, not a fresh audit that every feature is active or correctly configured in production. Consolidation is distinct from training model weights.

Trinity’s intended semantic compression retains selected durable contributions: new or reinforced relationships, supported attribute updates, provenance and new concepts when needed. Not every input produces every update. Explanatory notation is G(t+1) = U(G(t), delta(t)), where delta is a policy-accepted update package and U applies it.

Hierarchical interface nodes are a proposed organization of coherent subgraphs. A representation z(C) = S(G[C]) summarizes or provides access to a cluster. The exact automatic cluster-promotion mechanism, thresholds and preserve/archive/remove policy were not verified in the inspected material. The website’s three-input example is synthetic and retains its underlying records; it does not demonstrate production consolidation.

A summary is not generally invertible. Semantic compression loses original wording and omitted detail unless an original artifact is separately retained and remains accessible. Provenance identifies origins; it cannot reconstruct deleted information. Nodes, edges, metadata, indexes and retained sources all consume storage. Neither the artwork’s 4 GB labels nor its 10:1 ratio is a verified capacity or compression benchmark.

8. Semantic topology and display geometry

Trinity’s project model treats Trinity as the dominant weighted reference node. Relative weighting and the project’s “prime declination” terminology describe the organization around that anchor. The rendered field makes a constructed arrangement inspectable, with graph records and selected-node values supplying the interpretation.

The inspected manifold service implements a Trinity-centred Gaussian display potential: phi_T(x) = -lambda_T exp[-d(x,x_T)^2 / (2 sigma_T^2)]. Its plane channel uses hash-derived coordinates; a separate embedding-distance channel uses cosine distance when vectors are available. Coordinates, importance, confidence, display depth and semantic distance are distinct quantities. A Gaussian field does not by itself establish non-orientable topology or measured cognitive curvature.

The highlighted relationship in the supplied route captures is described by the project as an existing LTKG edge and the current calculation pathway for that relationship. The straight rendering and the surrounding curved display are different representations. Neither implies that the edge is a surface geodesic.

9. Beyond the node and the shared-field model

A node’s radius depicts one scalar, not the complexity of its content. Useful representation depends on records and relationships together: content, provenance, temporal state, relation meaning, weight, confidence and retrieval interpretation.

The website’s shared-field demonstration uses a separate illustrative construction: node kernels plus Gaussian influence integrated along defined edge paths. Dimensionless node and edge features share compatible units. Edge integrals use midpoint samples along quadratic Bezier paths chosen for readability, not derived semantic geometry. A display projection selects channels for height or colour; one scalar surface cannot encode every document, relation attribute or inference state.

This model is not the inspected Trinity-centred production calculation. Its controls change real synthetic field calculations without writing memory or invoking inference. The separate retrieval-score example combines similarity, importance and relational relevance with illustrative coefficients, not verified ranking defaults. Khepri/probability-foam artwork motivates local variation; no authoritative Khepri equation was found in the inspected core material. The website’s complex-valued field is a classical illustration, and squared magnitude is intensity rather than a normalized probability.

10. Instrumentation and operational visibility

Current Instruments captures show cognitive gauges, cycle trends, health state, serving tiers and fallbacks, memory indicators, API concurrency, credential roster, estimated credit resources and Raven activity. The public website now presents these as a compact gallery led by the concurrency graph—“Cortex’s ECG”—rather than claiming a live monitoring connection.

Health distinguishes protective HOLD from a fault. Normalized health-state thresholds and the cognitive stress gauge are separate scales. Missing sources should remain unknown or NO DATA rather than a guessed zero. Gateway concurrency is estimated from session logs; direct-path activity can be metered differently. Credit balances are local-ledger estimates from recorded funding and engine-reported costs, not verified provider prepaid balances.

Captured alerts, balances, key fingerprints and statuses belong to a recorded session. They are not current measurements or benchmarks. Instrument availability and API error classes help evaluate a run but do not prove correctness, authorization or memory promotion.

11. Trust, serving tiers and cryptographic commitments

Trinity Cognition, provider Bridge and Mock must remain distinguishable. The intended trust design binds the response and query hashes, telemetry, State Weaver sigil, serving tier and instance-identity commitment in a signed envelope. Bridge and Mock can have valid origin signatures while still displaying Unsealed Cognition: authenticity does not upgrade the serving tier.

Ed25519 is the selected signing method. Signing integration, the canonical envelope specification and public-key publication remain pending in this public account. The website’s Verify a Response dialog inspects prototype field presence only and must never be treated as signature verification. A captured Sealed status is not independent cryptographic evidence.

A signature can authenticate a record’s origin and integrity against a trusted key; it cannot establish factual truth, safe execution or the quality of cognition. Signing does not authorize writes. The inspected database connection layer was changed to reject its former in-memory error fallback; focused tests covered failed open, cleanup/retry and persistence. Reloading a running backend and end-to-end fallback enforcement require operational verification.

12. Architectural coupling and the holographic moat

The holographic moat describes the interdependence of Cortex execution, LTKG state and WARDEN policy. Reproducing routing code alone does not reproduce graph history, and a schema alone does not reproduce traversal and governance. This is an integration challenge, not an unbreakability theorem or a reason to rely on obscurity.

Copied data can remain valuable; a sufficiently complete snapshot can preserve state. Protect implementations with access control, least privilege, credential isolation, auditability, backups and security testing. The holographic and crystalline artwork is metaphorical. It does not establish a physical mechanism, prevent copying or replace a security audit.

13. Systemic emergence and the Klein Mirror

Trinity’s account of systemic emergence concerns feedback: accepted state updates change the context and constraints of later cycles. Distinct local execution scopes, exploration and constraint, conditional arbitration and task-state changes can contribute to trajectories not specified by a single response. Deterministic controls can organize probabilistic inference; correctness, beneficial novelty and stability still require measurement.

The Klein Mirror is a research analogy for computational self-reference. A Klein bottle is an intrinsically two-dimensional non-orientable surface that can be embedded without self-intersection in four-dimensional Euclidean space. Three-dimensional depictions can cross themselves; an additional spatial coordinate separates the overlapping points. Along a suitable orientation-reversing loop a local frame returns reversed, while not every closed loop does so.

Self-reference occurs when a system processes representations of its own structure, state or outputs; ordinary feedback alone is insufficient. Cortex can construct context, ENG/SYNTH produce perspectives, host routing conditionally invokes PRIME, authorized results are recorded and later context may retrieve those records. “The evaluator can step outside a local exchange without stepping outside the system.”

No equivalence between Trinity’s state space and Klein-bottle topology, physical quantum tunnelling, consciousness or privileged self-knowledge is established. The research question is whether compact architecture representations preserve enough relational structure for different providers to reconstruct consistent self-models.

14. Evaluation agenda

Compare matched tasks against single-model and alternative orchestration baselines, controlling provider/model versions, context, tool permissions, retrieval, budgets and routing. Report quality, evidence support, uncertainty, continuity, latency, errors and cost with sample sizes, exclusions and failures. Distinguish observed outputs from explanations inferred after the fact.

  • Governance: test attempted unauthorized writes, forged caller identity, blocked paths, tier mislabelling, unavailable databases and promotion holds.
  • Radar: test loop bounds, review ownership, stale watchers, retries, stopping conditions and permission transitions.
  • Retrieval and compression: measure source retention, exact-recovery conditions, abstraction loss, contradictory evidence, stale interfaces and workload-defined storage costs.
  • Field models: separate coordinate/layout changes from retrieval changes; ablate node and edge contributions and specify the metric and projection.
  • Self-model research: use context ablations, controlled provider comparisons, provenance traces and predefined behavioural consistency measures.
  • Cryptography: publish the envelope encoding, key identity and rotation policy, then test byte-level tampering, signature validation and tier binding independently of UI glyphs.

15. Evidence status and source basis

This edition draws on the current website, owner-supplied application captures and targeted read-only inspection of project code. Source-inspected files include ltkg_manager.py, knowledge_staging.py, consolidation_worker.py, dream_cycle.py, cortex.py, manifold_field.py and response schemas. These observations are not a deployed-runtime audit or a complete security review.

The website’s graph explorers, field controls, compression sequence and orientation demonstration use labelled synthetic or conceptual data. Their correctness as demonstrations is separate from engine conformance. This paper asserts no measured superiority, fixed system footprint, lossless semantic compression or unlimited information capacity.

The companion Trinity Code Schema remains a version 0.1 proposed interchange contract. It is not revised by this edition and does not automatically cover the newer task, topology or signing models. Runtime conformance, formal graph-curvature implementation and automatic interface-node consolidation remain evidence gaps.
