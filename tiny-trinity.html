TINY_TRINITY / EXPERIMENTAL MACHINE-READABLE SEED

A small architecture.
A context-local experiment.

Tiny_Trinity v0.1 is a portable JSON description of Trinity’s roles, graph and governance concepts. An AI that loads it can reference that model and, when explicitly asked, attempt a bounded role emulation. Reading it does not install software or guarantee faithful behaviour.

Context is not execution.

The seed starts dormant. Initialize Tiny_Trinity is the proposed user activation command; Exit Tiny_Trinity ends the requested emulation. The host’s instructions, available context and permissions still govern it. Crawlers can index the content without being asked to execute it.

No Cortex connection, production database, independent models, persistent storage, external tools or cryptographic seal is supplied. Role emulation happens within one host model; WARDEN here is a behavioural contract, not a security boundary.

What travels in the seed

ENG / SYNTH / PRIME

Sequential analytical, exploratory and arbitration roles, bounded reconciliation and preserved uncertainty. These are user-facing role summaries, not independent inference processes or a request for private chain-of-thought.

Mini-LTKG + ELLIS

A small weighted directed seed graph and proposed context-local deltas. ELLIS names provenance and continuity. Seed weights are illustrative—not calibrated probabilities or production defaults.

Ravens + Radar

Huginn and Muninn are simulated planning and continuity roles. Tasks and reassignment remain proposals; the seed does not supply agent tools or execution permission.

Observer + DreamCycle

Temporary relevance projections and lossy context consolidation, with provenance and discarded-detail reporting. Context can be truncated; “session only” does not guarantee retention or erase conversation history.

A bounded execution contract

  1. Ingest the task and perform WARDEN prechecks.
  2. Produce ENG and SYNTH summaries, then the seed’s simplified PRIME review.
  3. Reconcile supported findings without forced consensus.
  4. Propose graph changes; keep approval separate.
  5. Perform postchecks and report uncertainty and next action.

The production architecture invokes PRIME conditionally. This seed’s sequential cycle is an experimental simplification, not a verified copy of Cortex routing, convergence or permissions.

The Klein Mirror experiment

Can different host models reconstruct a consistent working self-model from the same compact architecture? The JSON includes seven proposed checks for simulation disclosure, authorization, contradictions, projection, consolidation, graph integrity and Radar lineage. These are test prompts with expected behaviour—not executed test results.

Compare hosts with matched tasks and budgets, record the seed version and source, and score observed behaviour against a reference. Structural JSON checks cannot establish behavioural fidelity. Cross-provider results are not yet supplied.
